### 4. 过程中发现并修掉的缺陷

| # | 缺陷 | 根因 | 处理 |
|---|---|---|---|
| 1 | 验收运行器退出码被覆盖（用法错误返回 1 而非 2，且子进程会莫名多跑一次截图批次） | `verify.gd` 与 `capture.gd` 都读 `OS.get_cmdline_user_args()`，且 `capture.gd` 把 `--case=` / `--out=` 当作**触发条件**；Capture 是 autoload，其 `get_tree().quit(1)` 覆盖了运行器先前的 `quit(2)` | `capture.gd` 触发条件收紧为**仅** `--shots` / `--shot=` / `--capture` / `--bench`；`--case=` / `--out=` / `--frames=` / `--warmup=` 降为纯修饰符。已登记 §3.4 与 §16 |
| 2 | `ROADMAP` 原风险描述「`SceneTree` 脚本无法访问 autoload」不准确 | 实测：autoload **节点**确实挂在 root 上（`get_root().get_node("Style")` 可用），真正的问题是 `--script` 模式下 autoload **标识符编译期不可解析**（`Identifier not found: Style`） | 已按实测改写 §5 S0.2 风险条目；`verify.gd` 文件头写明该硬约束 |
| 3 | `quit()` 之后仍会被调用一次 `_process`，导致 `--list` / 用法错误被当成一次真实运行 | Godot 主循环在 `_initialize` 中 `quit()` 后仍进入一次迭代 | 增加 `_halt` 早退标记 |

### 5. 重要发现：`B-` 视觉门禁阈值不可达（→ Q13）

实测**同参数、同构建、同 seed**的三次独立窗口渲染，两两差异为
**1.62% / 5.67% / 5.05%**（像素比，通道阈值 8/255）——比原定门禁 `< 0.1%` 高一到两个数量级。

原因已定位（架构性的，不是参数没调好）：

- `shaders/toon.gdshader:49` 植被风摆用内建 `TIME`；
- `shaders/water.gdshader:33/51/60` 水波与泡沫用内建 `TIME`；
- `scripts/clouds.gd:81` 云的高度漂移直接读 `Time.get_ticks_msec()`（连 `time_scale` 都无法冻结）。

⇒ `--frames=N` 只能对齐帧数，无法对齐动画相位；**当前工程在字节层面不存在可复现帧**。

这是 S0.1 的**阻塞项**：不改判据，S0.1 的 `B-` 项会恒失败。三个候选方案（见 `ROADMAP §14 Q13`）：
(a) 以「同构建噪声底」做相对门禁；(b) 增加 `--static` 截图模式屏蔽水/云/植被后要求逐位一致；
(c) 立项把动画时钟改为可注入（`TIME` → `u_time` uniform）。

**本次未擅自修改阈值**（`§0.5` 变更控制），仅在 ROADMAP 中登记 + 加注「裁定前不得判通过」。

## 2026-10-16 · S0.6 可复现渲染时钟 · ✅ 已验收

> 本条**取代**上一条记录的 §4「下一步」，其余内容保持不变。

**一句话**：动画时间全部收归 autoload `Clock`（着色器走可注入的全局 uniform `render_time`），
两个独立进程同参数截图做到**逐位一致**（`img_diff` 0 像素 / 0.0000%、sha256 相同）；
S0.1 及后续每一步的 `B-` 门禁自本步起**按逐位一致判定**（比原定 `< 0.1%` 更严）。

### 1. 交付物

| 文件 | 作用 |
|---|---|
| `scripts/render_clock.gd`（新，autoload `Clock`） | 唯一时间源：`t` / `dt` / `frame`、`set_deterministic(on, hz=60)`、`reset()`、`is_reproducible()`；每帧 `RenderingServer.global_shader_parameter_set("render_time", t)`；确定性模式按 `t = frame / hz` **计算而非累加**（避免浮点漂移） |

### 3. 过程中发现并修正的三个坑（均已写进代码注释与用例）

1. **`RenderingServer.global_shader_parameter_get_list()` 是编辑器专用 API**，运行期调用会报
   `This function should never be used outside the editor`。最初用它做"参数是否注册"的检测，
   结果是每次窗口运行都刷 ERROR 日志、且判定恒假。改用
   `ProjectSettings.has_setting("shader_globals/render_time")`；"值是否真的进了着色器"改由
   **帧数反向对照**实质验证，不靠渲染服务读回。
2. **除着色器与云外还有两处隐性不可复现源**：`player.gd` 竖直跟随的收敛程度取决于**物理步数**
   （随真实帧率浮动），以及 `main.gd` 的 **HUD FPS 读数**（HUD 在取景范围内）。前者在确定性模式下
   直接落到静止高度并清零 `_squash`，后者固定报 `Clock.hz`；交互模式两者的原行为都保留。
3. **漏写 `--` 分隔符会让整个验收套件静默挂死**：`OS.get_cmdline_user_args()` 只认 `--` 之后的参数，
   少了它 `capture.gd` 收不到 `--shots` 便不 `quit()`，而 `OS.execute` 没有超时——实测挂死 10 分钟。
   新增 `_exec_user()` 强制插入 `--` 并以 `--quit-after` 兜底，此类问题退化为"清单没写出"的显式失败。
